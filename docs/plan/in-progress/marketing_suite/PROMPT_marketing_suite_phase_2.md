# Pro Prompt — marketing_suite Phase 2

## Phase 2: Client Settings & Pixel Injection (P1)

### Primary role
FRONTEND

### Preferred tool
- [x] OpenCode CLI — fast UI generation for forms and settings.
- [x] SuperDesign — the "Marketing Settings" screen needs to wow the property managers.

### Context
- **Project**: GateFlow — Zero-Trust (ADS Design System)
- **Goal**: Allow property managers to set tracking pixels and inject them on public visitor landing pages.
- **Rule**: ADS tokens only (`var(--ds-...)`).

### Goal
Implement a premium UI to configure tracking pixel IDs and dynamically inject these pixels on the public QR shortid route.

### Scope (in)
- Update `Organization` schema: Add `pixelMetaId` and `pixelGtmId`.
- Create a new "Marketing" settings tab in `apps/client-dashboard`.
- Use `superdesign` to design a polished settings card with attribution previews.
- Injecting tracking pixel scripts on the dynamic HTML generated by `/s/[shortId]/route.ts`.

### Scope (out)
- CRM Webhooks (next phase).
- Actually verifying pixel fires on external dashboards (just confirm they are in the HTML).

### Steps (ordered)
1. **Schema Finalization**:
   - Add the pixel ID fields to `Organization`.
   - Update `pnpm prisma db push`.
2. **Design Pass**:
   - Run `superdesign create-design-draft` for the "Marketing Settings" card.
   - Use ADS tokens for consistency.
3. **Frontend Settings**:
   - Build the "Marketing" settings page/tab in `apps/client-dashboard`.
   - Implement the server action to save pixel IDs.
4. **HTML Injection**:
   - Update `apps/client-dashboard/src/app/[locale]/s/[shortId]/route.ts` to fetch organization settings.
   - Conditionally Append the GTM/Meta pixel scripts to the template if the organization has those IDs set.
5. **Verification**:
   - Navigate to `/s/{id}` in browser and inspect `<head>` for pixel scripts.
   - Confirm ADS tokens are used in the settings UI.

### Acceptance criteria
- [ ] UI for marketing settings is functional and matches ADS spec.
- [ ] Pixel scripts successfully appear on visitor landing pages when configured.
- [ ] `Organization` records correctly store pixel data.
- [ ] `pnpm turbo build --filter=client-dashboard` passes.
