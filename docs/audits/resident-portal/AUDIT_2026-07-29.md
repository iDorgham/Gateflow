## Executive verdict

Resident Portal has a usable App Router shell (responsive BottomNav/Sidebar,
visitor and open-QR forms, PWA stubs) but is **not pilot-ready**. Static
evidence shows missing auth redirects, wrong JWT org claim usage with
`dev-*-id` fallbacks, production-breaking localhost API rewrites for visitor
create, QR UI that does not render a scannable code, no i18n/`dir` RTL, and
zero app-local tests. Related plan
`docs/plan/Ready/resident_portal_responsive/` remains Planned; reference:
`docs/reference/apps/RESIDENT_PORTAL_REFERENCE.md`.

## Security findings (`static-review-only`)

### P0

1. **No login redirect; hard-coded identity fallbacks** —
   `claims?.sub || 'dev-resident-id'` and `claims?.org || 'dev-org-id'` on
   home, visitors, visitors/new, visitors/[id], open-qr/new, profile.
   Layout returns children when `!claims?.sub`.

2. **Wrong org claim on pages** — pages use `claims?.org` only; JWT interface
   and client-dashboard signing use `orgId`. Layout correctly falls back
   `(claims.org) || (claims.orgId)`.

3. **Visitor API rewrite pinned to localhost** —
   `next.config.js` rewrites `/api/resident/:path*` →
   `http://localhost:3001/api/resident/:path*`.

4. **QR not scannable** — `visitor-qr-card.tsx` renders monospace text in a
   placeholder box (comment: “Placeholder for QR Code”).

### P1

5. JWT secret fail-open: `_jwtSecret || 'dev-insecure-fallback-change-me'` in
   `src/lib/auth.ts`.
6. History/maintenance RSC fetch without cookies.
7. PII in offline queue (`pending-sync.ts` / `localStorage`).
8. Cross-subdomain session cookie sharing unproven for portal host.

### P2

9. Revoke / share / download UI non-functional.
10. CSRF pattern not visible on cookie-auth mutating fetches.
11. HMAC signing correctly lives in client-dashboard; portal does not mint
    unsigned codes but does not render usable QR either.

### P3 / positive

- No `dangerouslySetInnerHTML` found under resident-portal `src`.
- Soft-delete filters generally present on unit/user/QR queries.
- Notification/push API routes check session + `organizationId`.
