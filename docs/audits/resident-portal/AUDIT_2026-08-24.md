## 1. Overview & Architectural Role

`resident-portal` is a mobile-first Progressive Web Application (PWA) designed for compound residents, unit owners, and tenants. It empowers residents to generate secure single-use or recurring visitor passes, view entry history, manage family access, and submit maintenance tickets.

### Core Architecture

- **Framework:** Next.js 16 with PWA Service Worker (`next-pwa` / custom worker) for offline credential caching.
- **Upstream API Proxy:** Direct typed client consuming the core API via `@gate-access/api-client`.
- **Security & Scoping:** Session token bound to resident's specific `unitId` and `organizationId`. Revoking a pass immediately propagates fail-closed verification to gate scanners.
- **i18n & RTL:** Bilingual Arabic and English support with logical CSS styling and direction-agnostic flex layouts.

## 3. Pros and Cons Analysis

### Pros (Strengths)

1. **Lightweight Mobile-First PWA:** Installable on iOS/Android home screens without requiring App Store downloads.
2. **Offline Presentation Resilience:** Cached passes render with high-contrast QR display even when the resident is disconnected.
3. **Instant Pass Revocation:** Dynamic revocation invalidates HMAC payload nonces in the database within milliseconds.
4. **Intuitive Bilingual UX:** Polished Arabic (RTL) and English (LTR) transitions and typography.

### Cons (Weaknesses & Tech Debt)

1. **PWA Push Notification Constraints on iOS:** Web Push on iOS requires standalone home-screen installation (`display: standalone`).
2. **Lighthouse PWA Metric Soft-Skipping:** Automated CI soft-passes remote Lighthouse probes when production staging URLs are protected.
